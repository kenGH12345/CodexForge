# Sharding Strategy — 项目专家 skill 的分片组织宪法

> **本文件定义**：`gen-skill` 产出的项目专家 skill（`<skillsDir>/<project>/SKILL.md + references/*.md`）如何切分章节到哪些文件。
> **对位**：meta-skill 自身用 `skill-author-guide.md + skill-author-guide-refs/*.md` 就是这套规则的产出样例——**自举**。

---

## §1 为什么分片（Why）

### 1.1 自举原则

meta-skill 体系本身采用了"主文件 + `<name>-refs/` 分片"的组织形态。如果 meta-skill 的产出物（项目专家 skill）却用**单文件**形态，就违反了"**元层的设计原则应适用于实例层**"这一基本要求。v2.1 修正这一不一致。

### 1.2 Token 经济学

任何项目专家 skill 总量都会膨胀（典型在 500~3000 行）。但**读者（LLM Agent）在做具体任务时，通常只关心 1~2 个象限**：
- 排查协议兼容问题 → 只需读 D4 契约象限（~250 行）
- 分析事件流 → 只需读 D2 行为 + D3 通讯（~500 行）
- 新人入门 → 只需读主文件（~250 行）

单文件形态下，每次任务都要全量加载 500~3000 行；分片形态下按需加载，**通常节省 60~80% token**。

### 1.3 局部可演进

分片后任一象限的 skill 知识可独立迭代，不会影响其他象限。例如项目的协议层重构只需更新 `d4-contract.md`，其他 4 个文件不受影响。

## §2 四强制规则（Sharding Constitution）

### R-A：主文件必含内容

`SKILL.md` 主文件**必须包含且仅包含**：

1. **项目指纹块**（YAML + 项目名/语言/规模/主范式的一句话概述）
2. **§1 项目概览**（综合维度，跨象限）
3. **§M-3 新人 Onboarding 路径**（跨象限元维度）
4. **四象限导航表**（索引：每节对应哪个分片文件 + 一句话简介）
5. **分片自检矩阵**（落盘前 12 问的结果）

❌ 主文件**禁止**放单象限的详细内容（那些去分片）。

### R-B：章节象限归属表（硬规则）

17 节 + 3 元节按以下**固定归属**分布到 5 个文件：

| 章节 | 归属文件 | 象限 |
|---|---|---|
| §1 项目概览 | **SKILL.md** | 综合 |
| §2 项目流程与生命周期 | `references/d2-behavior.md` | D2 |
| §3 模块管理 | `references/d1-structure.md` | D1 |
| §4 设计模式 | `references/d2-behavior.md` | D2 |
| §5 架构框架（MVC/分层）| `references/d1-structure.md` | D1 |
| §6 事件系统 | `references/d3-communication.md` | D3 |
| §7 状态管理 | `references/d2-behavior.md` | D2 |
| §8 配置与数据驱动 | `references/d4-contract.md` | D4 |
| §9 持久化与存档 | `references/d4-contract.md` | D4 |
| §10 网络通信 | `references/d3-communication.md` | D3 |
| §11 日志系统 | `references/d2-behavior.md` | D2 |
| §12 公共组件与工具库 | `references/d1-structure.md` | D1 |
| §13 MVC 数据流与绑定 | `references/d3-communication.md` | D3 |
| §14 模块间通讯契约 | `references/d3-communication.md` | D3 |
| §15 协议与契约定义 | `references/d4-contract.md` | D4 |
| §M-1 错误处理与容错 | `references/d4-contract.md` | D4 |
| §M-2 修改影响半径 | `references/d3-communication.md` | D3 |
| §M-3 新人 Onboarding | **SKILL.md** | 元 |

**归属不允许偏离**。若你觉得某节"两边都像"，查 §3 归属决策树，否则按表格。

### R-C：跨分片引用语法

当一个章节需要引用另一个分片里的章节时：

✅ **正确**：
```markdown
详见 [§5 架构框架](../references/d1-structure.md#5-架构框架)
参考 [§M-2 影响半径](./d3-communication.md#m-2-修改影响半径)
```

❌ **禁止**：
- 只写"参见 §5"不给链接（用户跳不到）
- 写绝对路径（破坏项目迁移性）
- 写外部 URL（破坏离线可读）

### R-D：分片大小上限

- **主文件**：≤ 300 行（Token 成本优先）
- **每个分片 refs**：≤ 350 行（若超过，考虑再拆或证据精简）
- **整体合计**：目标 ~2000 行（不含代码块），上限 3500 行

超出上限时**必须再切**：方法是把该分片里"内容最长的章节"抽出成独立子分片（如 `d3-communication-network.md`），并在 R-B 表里登记。

## §3 归属决策树（边界章节怎么归）

当某节归属模糊时按以下决策链判定：

```
问 Q1：这节主要回答"空间如何组织" vs "时间如何演进" vs "跨组件交换" vs "边界约定"？
├── 空间 → D1 结构
├── 时间 → D2 行为
├── 跨组件 → D3 通讯
└── 边界 → D4 契约
```

### 典型边界案例

| 节 | 第一直觉 | 最终归属 | 理由 |
|---|---|---|---|
| §5 架构框架（MVC/分层）| D1 或 D3 | **D1** | "分层"首先是空间组织；"跨层通讯"由 §14 独立回答 |
| §13 MVC 数据流 | D1 或 D3 | **D3** | 核心是"数据→视图"的**流动方向**，通讯优先 |
| §M-2 修改影响半径 | D3 或 元 | **D3** | 影响半径本质是 callEdges 拓扑 |
| §M-3 新人路径 | 元 或 D1 | **SKILL.md** | 跨象限，每次都要读，Token 价值最高 |
| §1 项目概览 | 元 或 SKILL.md | **SKILL.md** | 同上 |

## §4 小项目降级策略

并非所有项目都需要 5 个文件。当以下条件满足时，允许降级：

| 项目规模 | 建议形态 |
|---|---|
| **极小**（单文件工具 / < 500 行源码） | 单文件 `SKILL.md`（只写主文件内容 + 选几节最关键的放进来），附注"本项目规模不足以应用分片策略" |
| **小**（1~2 个象限有实质内容）| 主文件 + 1~2 个分片（只写有内容的象限） |
| **中**（3 个象限）| 主文件 + 3 个分片（缺的象限在主文件导航表中标 N/A） |
| **标准**（4 个象限都有内容）| 标准 5 文件形态 |
| **大**（单分片超 350 行）| 再切（见 R-D）|

**降级必须明说理由**：在主文件开头加一句"本项目采用简化分片：<理由>"。

## §5 反模式

### 反模式 1：过度分片

❌ 一节一文件（17 个 md）——查找成本高，章节间连接被人为割裂。
✅ 按 4 个正交象限 + 元维度（SKILL.md），共 5 个文件。

### 反模式 2：孤立分片

❌ 分片中完全没有跨引用，像 5 个无关文档。
✅ D3 引用 D1 模块结构、D4 引用 D3 协议传输，使用 R-C 语法建立可跳转链接。

### 反模式 3：循环引用链

❌ `d1 → d2 → d3 → d1` 的循环引用。
✅ 保持**单向依赖偏好**：D1 < D2 < D3 < D4（上层可引用下层，反之应精简到极少）。

### 反模式 4：主文件臃肿

❌ 主文件 600 行，把所有"重要内容"都塞进来。
✅ 主文件严格按 R-A 5 项内容，绝不超 300 行。

### 反模式 5：归属偏离

❌ 把 §13 MVC 放到 d1-structure.md（"因为 MVC 是架构模式啊"）。
✅ 查 R-B 表：§13 → d3-communication.md，归属由规则决定，不由个人偏好决定。

## §6 验收自检 3 问

落盘分片前必答：

### Q1：主文件 ≤ 300 行？
- 方法：`wc -l SKILL.md`（或等效工具）
- 若超出，识别最长的章节是否违反 R-A，若是则搬到对应分片

### Q2：章节归属符合 R-B 表？
- 方法：grep 所有章节标题 `^## §` 然后逐个比对 R-B 表
- 若偏离，按 R-B 表校正（不要反向修改 R-B）

### Q3：跨分片引用链接全部有效？
- 方法：检查每个 `[...](../references/d?-xxx.md#...)` 链接，确认目标文件存在且锚点名匹配
- 若链接失效，要么修目标锚点，要么修引用路径

## 附录 B：本文件和 meta-skill 其他文件的关系

- **skill-author-guide.md**（主文件）：**WHAT + WHEN**（写什么 + 什么时候写）
- **dimension-framework.md**：**WHY**（四维完备性论证）
- **p0-dimensions.md**：**HOW DEEP**（每节要多深的 rubric）
- **examples.md**：**HOW IT LOOKS**（好坏例对比）
- **evidence-recipes.md**：**HOW TO EXTRACT**（调研配方）
- **sharding-strategy.md**（本文件）：**HOW TO ORGANIZE**（组织到什么文件）

六者正交不重叠，组成完整的 meta-skill 知识链。
