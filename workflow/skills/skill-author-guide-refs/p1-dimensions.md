## §P1-1 资源管理

### 触发条件
- 游戏项目（Unity/UE/Cocos）— 必写
- 移动端项目（iOS/Android 原生）— 必写
- 桌面应用带资源打包 — 必写
- 纯后端服务 — 通常跳过

### 核心问题
1. 项目主要管理什么资源？（贴图/音频/网络资源/数据包）
2. 资源加载策略是？（同步/异步/预加载/按需/流式）
3. 资源释放时机和引用计数怎么处理？
4. 资源打包流程？（AssetBundle/APK obb/等）
5. 常见资源泄漏点？

### 最低证据
- ≥ 3 个文件路径（资源管理器 / 加载器 / 释放逻辑）
- ≥ 1 段加载代码
- 1 条"本项目主要资源类型 + 估算资源量"

## §P1-2 并发与异步模型

### 触发条件
- 项目使用协程（Unity Coroutine / Go goroutine / Kotlin coroutine）— 必写
- 项目有显式多线程 — 必写
- 后端高并发服务 — 必写
- 单线程 UI + 回调（仅 DOM/Node 单线程）— 可简写

### 核心问题
1. 项目使用哪种并发模型？（协程/线程/Promise/async-await/事件循环）
2. 哪些操作是异步的？边界在哪？
3. 共享状态的同步机制？（锁/CAS/无锁结构）
4. 异步错误如何传播？
5. 常见的并发坑？（死锁/竞态/Promise 链断裂）

### 最低证据
- ≥ 3 个文件路径（典型异步代码 / 锁或同步原语 / 异步错误处理）
- ≥ 1 段并发代码片段

## §P1-3 性能关键路径

### 触发条件
- 游戏项目有帧率要求 — 必写
- 实时通信/音视频 — 必写
- 高并发后端 — 必写
- 工具类脚本 — 跳过

### 核心问题
1. 性能敏感的核心循环在哪？（主循环/热路径）
2. 哪些区域禁止分配内存/触发 GC？
3. 已知的性能热点 hotspots？
4. 性能监测怎么做？（profiler/metrics/APM）
5. 如何判断一段新代码"会不会拖慢核心路径"？

### 最低证据
- ≥ 3 个文件路径（主循环 / 典型热路径 / 性能监控）
- ≥ 1 段带性能约束注释的代码

## §P1-4 构建与部署

### 触发条件
- 所有项目都应有简版（即使只是 `npm start` 也要说）

### 核心问题
1. 构建命令和产物？
2. 环境差异怎么处理？（dev/staging/prod）
3. 部署方式？（Docker/k8s/裸机/静态托管/APK/IPA）
4. CI 流程走哪些步骤？
5. 版本号规则？

### 最低证据
- ≥ 2 个文件路径（`package.json` scripts / Dockerfile / CI 配置）
- ≥ 1 段典型 CI 片段或 Docker 步骤

## §P1-5 测试策略

### 触发条件
- 所有项目都应写（即使没测试也要说明"无测试"及原因）

### 核心问题
1. 测试框架是？
2. 测试层次划分？（单测/集成/E2E）
3. Mock 约定？
4. 测试文件物理位置？
5. 跑测试的命令？
6. 新加代码的测试要求？

### 最低证据
- ≥ 2 个文件路径（测试示例 / 测试配置）
- ≥ 1 段代表性测试代码

## §P1-6 术语词典

### 触发条件
- 项目有领域术语/黑话 — 必写（几乎所有非工具类项目都有）
- 纯通用库 — 可跳过

### 核心问题
1. 项目中有哪些"只有本项目才懂"的术语？
2. 每个术语的定义？
3. 术语对应到代码里的哪些符号/文件？

### 最低证据
- ≥ 5 个术语条目
- 每个术语至少关联 1 个代码位置（文件:行）
- **来源**：从 `codeGraph.symbols[]` 找高 `cb` 且语义特殊的类名（例如游戏项目的 "Cabin" / "Garage" / "Lottery"）

### 输出格式建议
表格：

| 术语 | 定义 | 代码位置 | 首次出现 |
|---|---|---|---|
| ... | ... | `Assets/Scripts/Cabin/...` | v1.0 |

## 使用提示

P1 维度**不必追求全覆盖**。判断原则：
- 项目真的有该维度 → 按 rubric 写
- 项目没有 → 跳过该节（不要硬凑）
- 拿不准 → 跳过（P1 是锦上添花，P0 才是地基）
